#+title: Orgx Bulk Operations Guide
#+author: tychoish
#+language: en

=orgx-bulk= layers resumable bulk operations on top of Org's built-in =org-agenda-bulk-action=. Plan storage, execution, the review buffer, MCP tools and =agent-shell-queue= (ASQ) integration are provided by the =hitl= package (=hitl-plan=, =hitl-plan-ui=, =hitl-plan-mcp=), which orgx requires (=hitl= 0.1.0 or newer).

The unit of work is an *agenda buffer*. With =org-agenda-sticky= enabled, each sticky agenda buffer acts as an isolated batch with its own buffer-local marks and optional ASQ queue bucket.

* Architecture

orgx owns only the =org-agenda= domain, which =orgx-bulk.el= registers on =hitl-plan= with [[file:../../hitl/hitl-plan.el::hitl-plan-register-domain][~hitl-plan-register-domain~]]. The domain consists of four pieces:

- *Operations*: the 11 built-in operations in [[file:../lisp/orgx-bulk-ops.el::orgx-bulk-register-op][=orgx-bulk-ops.el=]] and the [[file:../lisp/orgx-bulk.el::orgx-bulk-register-op][~orgx-bulk-register-op~]] function that defines them.
- *Entry points*: =B= in agenda buffers ([[file:../lisp/orgx-bulk-agenda.el::orgx-agenda-bulk-action][~orgx-agenda-bulk-action~]]), =C-c o b= ([[file:../lisp/orgx-bulk.el::orgx-bulk-todo-state][~orgx-bulk-todo-state~]]) and =C-c o B= ([[file:../lisp/orgx-bulk-buffer.el::orgx-bulk-resume][~orgx-bulk-resume~]]).
- *Scope builder*: [[file:../lisp/orgx-bulk-agenda.el::orgx-bulk-batch-for-scope][~orgx-bulk-batch-for-scope~]] turns a scope (marked agenda entries, a file list, agenda files or denote files) into a sticky agenda buffer and its targets.
- *Denote sync hook*: [[file:../lisp/orgx-bulk.el::orgx-bulk-denote-sync-execution-status][~orgx-bulk-denote-sync-execution-status~]] runs from [[file:../lisp/orgx-bulk.el::orgx-bulk-after-apply-functions][~orgx-bulk-after-apply-functions~]].

Other packages provide everything else, as the table shows:

| Concern | Provided by |
|---------+-------------|
| Plan structs, persistence, execution, ids | =hitl-plan= |
| Review buffer (=hitl-plan-mode=) | =hitl-plan-ui= |
| Generic plan tools over MCP | =hitl-plan-mcp= |
| Queue item kind =hitl-plan= | =agent-shell-queue-plan= |

* Quickstart

1. Mark entries in an agenda buffer with =m= (=org-agenda-bulk-mark=) or =*= (=org-agenda-bulk-mark-all=).
2. Press =B= (=orgx-agenda-bulk-action=) to choose an operation from the registry and build a persisted plan.
   - The plan opens in a review buffer (=*hitl-plan: <id>*=); execute it from there.
   - With =C-u B= the plan executes immediately instead.
3. Resume an interrupted or draft plan at any time:
   - Key: =C-c o B=
   - Command: ~M-x orgx-bulk-resume~

~C-c o b~ (~orgx-bulk-todo-state~) is a shortcut for the common case: it prompts for a target state and a scope (the agenda's marked or all entries, the current buffer, agenda files or denote files), then opens a =todo-state= plan in the review buffer.

* Agenda Driver (=B=) and Prefix Arguments

In =org-agenda-mode= (when =orgx-agenda-minor-mode= is active), =B= runs ~orgx-agenda-bulk-action~:

| Invocation | Behavior |
|------------+----------|
| =B= | Build the plan and open it in the review buffer without executing |
| =C-u B= | Build the plan and execute it immediately through ~orgx-bulk-execute~ |
| =0 B= | Force ~orgx-bulk-log-notes~ to =ignore= for this run |
| =1 B= | Force ~orgx-bulk-log-notes~ to =one= (prompt once for a shared note) |
| =2 B= | Force ~orgx-bulk-log-notes~ to =each= (prompt per heading during execution) |

* Plan Review Buffer (=hitl-plan-mode=)

A review buffer (=*hitl-plan: <id>*=) shows the plan metadata, the operation pipeline, and each step's status, file and heading. The buffer uses [[file:../../hitl/hitl-plan-ui.el::hitl-plan-mode][~hitl-plan-mode~]], with ~orgx-bulk-plan-mode~ as an alias, and [[file:../lisp/orgx-bulk-buffer.el::orgx-bulk-review][~orgx-bulk-review~]] creates or refreshes it.

| Key | Command | Description |
|-----+---------+-------------|
| =C-c C-c=, =c= or =x= | ~hitl-plan-ui-execute~ | Execute all pending steps in the plan |
| =m= / =u= | ~hitl-plan-ui-toggle-skip~ | Toggle the step at point between =pending= and =skipped= |
| =a= | ~hitl-plan-ui-add-op~ | Append another operation to the plan (archive/refile are automatically ordered last) |
| =n= | ~hitl-plan-ui-edit-note~ | Set or edit the per-step log note (or plan-wide note on header lines) |
| =L= | ~hitl-plan-ui-cycle-log-notes~ | Cycle the plan's ~log-notes~ mode (=ignore= -> =one= -> =each=) |
| =RET= | ~hitl-plan-ui-visit-target~ | Visit the target Org heading in another window |
| =g= | ~hitl-plan-ui-refresh~ | Re-resolve targets, refresh agenda marks, and redraw |
| =d= / =k= | ~hitl-plan-ui-discard~ | After confirmation, mark the plan =discarded=, save it (the =.eld= file is kept) and close the buffer |
| =q= | ~quit-window~ | Bury the review buffer (plan remains saved on disk) |

If you press =C-g= during execution, completed steps remain recorded as =done= on disk, the remaining steps stay =pending=, and the plan status becomes =paused=. Run ~M-x orgx-bulk-resume~ (=C-c o B=) to reopen the plan and continue.

* Log-Note Modes and Blocking Policy

** Note Logging (~orgx-bulk-log-notes~)
When changing TODO states to or from keywords configured with =@= (such as =DONE(d@)=), ~orgx-bulk-log-notes~ controls how notes are recorded:

- ='ignore= (default) :: Suppress all log-note prompts during bulk execution.
- ='one= :: Prompt once when the plan is created (or use the plan's =:note= field) and inject that note into every heading's logbook.
- ='each= :: Prompt for a note on each heading as it is processed (or use the step's pre-populated =:note=). Pressing =C-g= at a prompt pauses the plan cleanly.

** Blocking Policy (~orgx-bulk-inhibit-blocking~)
By default (~orgx-bulk-inhibit-blocking~ is =nil=), bulk =todo-state= changes honor ~org-enforce-todo-dependencies~, ~org-enforce-todo-checkbox-dependencies~, and ~org-blocker-hook~ (including Orgx's =:question:= blocker). Blocked headings are recorded as =failed= with the blocker reason while the rest of the batch continues. Set ~orgx-bulk-inhibit-blocking~ to =t= to bypass blocking rules during bulk operations.

** Hooks

Two abnormal hooks let you react to execution:

- ~orgx-bulk-step-functions~ :: Runs after each step succeeds. Each function receives the =hitl-plan-step= and its =hitl-plan=, with point on the heading.
- ~orgx-bulk-after-apply-functions~ :: Runs once per touched file after execution. Each function receives the file, the done steps for that file and the plan. The default value is ~orgx-bulk-denote-sync-execution-status~, which sets =#+execution_status:= in denote plan files to =in-progress= or =complete=.

** Target Identification (~orgx-bulk-assign-ids~)
By default (~orgx-bulk-assign-ids~ is =nil=), headings without an =ID= or =CUSTOM_ID= are resolved by file, outline path, heading title, and position hint (checking nearest line number when duplicate sibling titles exist). Set ~orgx-bulk-assign-ids~ to =t= to assign an ~org-id~ to every targeted heading when a plan is created.

* Built-in Operations & Custom Operation Registry

Built-in operations registered in =orgx-bulk-ops.el= (the =Key= is the character read by the =B= prompt):

| Name | Key | Queueable | Description |
|------+-----+-----------+-------------|
| =todo-state= | =t= | Yes | Change TODO state |
| =tag-add= | =+= | Yes | Add one or more tags |
| =tag-remove= | =-= | Yes | Remove one or more tags |
| =schedule= | =s= | Yes | Set or clear (=none=) SCHEDULED timestamp |
| =deadline= | =d= | Yes | Set or clear (=none=) DEADLINE timestamp |
| =priority= | =p= | Yes | Set priority (=A=, =B=, =C=) or clear (=none=) |
| =property-set= | =P= | Yes | Set a drawer property =NAME= to =VALUE= |
| =refile= | =r= | Yes | Refile subtree to target file and heading (ordered last) |
| =archive= | =$= | Yes | Archive subtree via ~org-archive-subtree~ (ordered last) |
| =archive-sibling= | =A= | Yes | Archive subtree to archive sibling (ordered last) |
| =function= | =f= | No | Call an Emacs Lisp function at each heading |

** Registering a Custom Operation
Use ~orgx-bulk-register-op~ to add your own operation to the =B= prompt, plan serializer, ASQ queue, and MCP server. It registers the operation in the =org-agenda= domain with ~hitl-plan-register-op~ and bridges =:key= into ~org-agenda-bulk-custom-functions~. Keys that collide with =org-agenda-bulk-action= built-ins or existing operations signal an error. =:order-last= (as used by =refile= and the archive operations) sorts the operation after the others in a plan:

#+begin_src elisp
(orgx-bulk-register-op 'effort-set
  :key ?e
  :label "effort"
  :queueable t
  :read-args (lambda ()
               (list (read-string "Effort (e.g. 0:30): ")))
  :validate (lambda (effort)
              (when (string-empty-p effort)
                "effort cannot be empty"))
  :apply (lambda (effort)
           (org-set-effort nil effort))
  :describe (lambda (effort)
              (format "effort = %s" effort))
  :from-json (lambda (args)
               (list (alist-get 'effort args)))
  :schema '((:name "effort" :type "string" :description "Effort duration string")))
#+end_src

Existing entries in ~org-agenda-bulk-custom-functions~ are also bridged automatically as =function= operations (~orgx-bulk-op-for-key~).

* Queuing on Sticky Agenda Buffers (=agent-shell-queue=)

Any live =org-agenda-mode= buffer can be an ASQ target buffer, and =agent-shell-queue-plan= (see its Execution Control docs) handles the queueing itself. Queue items have kind =hitl-plan=. =orgx-bulk-asq.el= builds the plan from the agenda buffer and keeps [[file:../lisp/orgx-bulk-asq.el::orgx-bulk-asq-dispatch][~orgx-bulk-asq-dispatch~]] and [[file:../lisp/orgx-bulk-asq.el::orgx-bulk-asq-max-items][~orgx-bulk-asq-max-items~]] as aliases of the =agent-shell-queue-plan= definitions. The command has these properties:

- *Command*: [[file:../lisp/orgx-bulk-asq.el::orgx-bulk-asq-enqueue][~M-x orgx-bulk-asq-enqueue~]], optionally given a plan or operation and a =delay-after=.
- *Scope*: it enqueues the entire marked set (else the batch, else all entries) in the target agenda buffer as a single queue item.
- *Freezing and locking*: it freezes the plan's step list at enqueue time and locks marks in the agenda buffer ([[file:../lisp/orgx-bulk-agenda.el::orgx-bulk-batch-locked][~orgx-bulk-batch-locked~]]) until all queued =hitl-plan= items on that buffer complete. The =org-agenda= domain supplies the lock as =:lock-batch=, called with =(buf plan-id)=, and the unlock as =:unlock-batch=, called with =(buf)=. The domain's =:accept-buffer= makes any agenda buffer a valid target.
- *Limits*: ~orgx-bulk-asq-max-items~ (an alias of ~agent-shell-queue-plan-max-items~, default =5=) caps the items per agenda buffer, and the queue rejects non-=:queueable= operations (such as =function=) and =each= note mode. When you run the command interactively, a plan built by ~orgx-bulk-asq-enqueue~ falls back from =each= to =ignore=.
- *Pacing*: the item's =delay-after=, or ~agent-shell-queue-default-pause-delay~, separates consecutive queued batches.

* MCP Tools (=orgx-mcp.el=)

The =orgx= MCP server exposes six bulk-operation tools, each a thin wrapper around a generic =hitl-plan-mcp= tool ([[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-ops][~hitl-plan-mcp-ops~]], [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-create][~hitl-plan-mcp-create~]], [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-list][~hitl-plan-mcp-list~]], [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-status][~hitl-plan-mcp-status~]], [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-discard][~hitl-plan-mcp-discard~]] and [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-mcp-execute][~hitl-plan-mcp-execute~]]). Each wrapper scopes the call to the =org-agenda= domain and to [[file:../lisp/orgx-bulk.el::orgx-bulk-directory][~orgx-bulk-directory~]]:

- =bulk_ops= :: Lists the registered bulk operations with their keys, queueable flags and parameter schemas.
- =bulk_plan_create= :: Collects headings from a =scope= (=files=, =agenda_files=, =denote= or =agenda=) and persists a plan (=status: "draft"=) with a preview of the steps. The arguments =match=, =from_states=, =files= and =buffer_name= refine the scope, and the review buffer opens unless =show= is false. This is the only tool that translates its arguments (orgx scope names and =message= become a scope and a note). A temporary agenda buffer built to collect the headings is killed afterwards, a pre-existing one is left alone, and execution rebuilds its own batch.
- =bulk_plan_list= :: Lists saved plans, optionally filtered by =status=.
- =bulk_plan_status= :: Returns the full step-by-step status and summary counts for a =plan_id=.
- =bulk_plan_discard= :: Marks a plan =discarded=, saves it (the =.eld= file is kept) and closes its review buffer.
- =bulk_plan_execute= :: Executes or resumes a saved plan, skips the =exclude= step ids with the message "excluded over MCP", and re-renders a live review buffer afterwards. The variable [[file:../../hitl/hitl-plan.el::hitl-plan-agent-may-apply][~hitl-plan-agent-may-apply~]] (~orgx-mcp-agent-may-apply~ is an alias) gates execution. When it is =nil=, the tool opens the review buffer and returns =awaiting_user_confirmation=.

** The =orgx-bulk-plan-*= accessors are gone and hitl generates plan ids

Call the =hitl-plan= functions directly ([[file:../../hitl/hitl-plan.el::hitl-plan-id][~hitl-plan-id~]], ~hitl-plan-step-status~, [[file:../../hitl/hitl-plan.el::hitl-plan-save][~hitl-plan-save~]], [[file:../../hitl/hitl-plan.el::hitl-plan-add-op][~hitl-plan-add-op~]] and the rest), because orgx removed the old =orgx-bulk-plan-*=, =orgx-bulk-step-*= and =orgx-bulk-op-*= accessor aliases, along with wrappers such as ~orgx-bulk-save~, ~orgx-bulk-plan-add-op~, ~orgx-bulk-get-op~ and ~orgx-bulk-describe-op~. What remains is orgx's own surface: the commands and user options above, ~orgx-bulk-register-op~, [[file:../lisp/orgx-bulk.el::orgx-bulk-create-plan][~orgx-bulk-create-plan~]], [[file:../lisp/orgx-bulk.el::orgx-bulk-execute][~orgx-bulk-execute~]], [[file:../lisp/orgx-bulk.el::orgx-bulk-get-plan][~orgx-bulk-get-plan~]], [[file:../lisp/orgx-bulk.el::orgx-bulk-list-plans][~orgx-bulk-list-plans~]], [[file:../lisp/orgx-bulk.el::orgx-bulk-discard][~orgx-bulk-discard~]], [[file:../lisp/orgx-bulk.el::orgx-bulk-load][~orgx-bulk-load~]] (which accepts a plan id, an absolute path, or a name ending in =.eld=) and ~orgx-bulk-review~. ~orgx-bulk-discard~ marks a plan =discarded=, saves it and kills its review buffer. The =orgx-bulk-buffer-*= command names in =orgx-bulk-buffer.el= are aliases of the =hitl-plan-ui-*= commands. orgx also removed the ~orgx-bulk-review-threshold~ option, so =B= always opens the review buffer and =C-u B= executes. Plan ids now come from hitl.

** Behavior changes since the move onto =hitl-plan=

The move changed seven behaviors:

- *MCP restrictions*: MCP accepts only =:queueable= operations (so =function= is rejected) and rejects =each= note mode. Handlers never prompt.
- *Error shape*: hitl returns failures as =(:error MESSAGE)= plists.
- *Summary steps*: each step carries a =label= field (the target heading) alongside =file=.
- *Plan ids*: they now look like =plan-YYYYMMDD-HHMMSS-XXXX=.
- *Old queue items*: queue items of the old =orgx-bulk= kind no longer dispatch, so re-enqueue those plans to get =hitl-plan= items.
- *Newer files*: older orgx can't read plan =.eld= files that the new code writes.
- *Older files*: orgx-only plan files without =:domain= still load through the domain's =:migrate-plist=, which is [[file:../lisp/orgx-bulk.el::orgx-bulk--normalize-legacy][~orgx-bulk--normalize-legacy~]].

* Security Model

orgx treats the external agent that calls the MCP tools (=bulk_*= and =org_capture_*=) as untrusted, because a prompt injection may have compromised it. Plans and commands you run yourself aren't restricted. The "Security model" section of hitl's README covers the shared side of this policy.

** Plans from MCP need your approval before they run

- *Origin and approval*: plans created by =bulk_plan_create= carry =:origin mcp=, which hitl sets and arguments can never override. Nothing runs until you approve it, and ~hitl-plan-agent-may-apply~ (alias ~orgx-mcp-agent-may-apply~, default =nil=) is the only switch that lets ~bulk_plan_execute~ apply a plan. When the switch is off, the tool shows the review buffer without taking focus and returns =awaiting_user_confirmation=.
- *Review and queue*: executing such a plan from its review buffer asks for an explicit =yes= that names the plan, its operations and its step count. Queueing the plan with ~orgx-bulk-asq-enqueue~, a command you run, approves it for one queued run.
- *Discard*: =bulk_plan_discard= discards only plans of origin mcp.
- *Trust boundary*: these gates assume the agent has no eval-capable tool. An agent that can run ~emacs_eval~ or Bash already has full access to the session, which is the same trust boundary as shell access, so this document leaves that case out of scope.

** Restrictions on origin-mcp plans

Each restriction below applies to plans of origin mcp, except where a bullet says otherwise:

- *Allowed files*: scope files, target =:file= values, refile destinations and archive destinations must be local, existing Org files (=.org= or =.org_archive=). Each must be in [[file:../lisp/orgx-bulk.el::orgx-bulk-mcp-allowed-files][~orgx-bulk-mcp-allowed-files~]] (files, or directories covering the Org files beneath them), in ~org-agenda-files~, or under =denote-directory=. orgx resolves symbolic links first and rejects remote (TRAMP) names without contacting the host. A disallowed file, a missing file and a non-Org file all produce the same error, so the check can't probe the file system.
- *File opening*: orgx opens files with file-local and directory-local variables disabled, and kills the buffers a =bulk_plan_create= call opened once the call finishes.
- *Targets*: orgx resolves and captures each target an agent supplies afresh, so the stored target (and with it the label, id and position in the review) is the real heading. A target must give =id= or =heading=, and any =id=, =heading=, =outline-path= or =pos= it states must agree with the heading it resolves to, or the call fails and names the target. Execution resolves the stored capture.
- *Scope*: orgx matches the scope =type= as a string. The =agenda= scope needs the name of an existing agenda buffer (=buffer_name=) and never falls back to the current buffer. The =agenda_files= and =denote= scopes ignore any file list supplied.
- *Operations*: =tag-add= and =tag-remove= need a single valid Org tag (=org-tag-re=, no whitespace or newlines). The =property-set= operation needs a one-word name without =:= and a one-line value, and refuses ARCHIVE (and =ARCHIVE*=), CATEGORY, ID, COLUMNS, LOGGING, STYLE, =EXPORT_*=, =header-args*= and any name in ~org-special-properties~, in any letter case or with a =+= suffix. The ID denial exists because an agent-set ID could hijack heading lookups, and Org and orgx assign IDs themselves (see ~orgx-bulk-assign-ids~). The tag and property syntax checks apply to everyone, while the property denylist applies only to origin mcp.
- *Archive*: =archive= checks the ARCHIVE property in effect when the step runs, and the property must name an allowed, existing file. Without that property, the global ~org-archive-location~ is your own setting and only has to be local. An archive file outside the allowed set, such as a normal =foo.org_archive= in a directory that isn't allowed, therefore fails the step until you add it to ~orgx-bulk-mcp-allowed-files~.
- *Limits*: =bulk_plan_create= type checks its arguments and caps their size with [[file:../../hitl/hitl-plan-mcp.el::hitl-plan-max-steps][~hitl-plan-max-steps~]] (1000) and ~hitl-plan-max-string-length~ (4096). Every failure returns =(:error MESSAGE)=.

** Capture tools reject heading and body text that could change the capture

=org_capture_task=, =org_capture_journal= and =org_capture_clock_in= require string =heading= and =body= arguments. The tools turn a heading's newlines and control characters into spaces. A body may span several lines, but no line may start with =#+begin_src=, =:PROPERTIES:=, =# Local Variables= or a heading (=* =), and the call returns =(:error MESSAGE)= when one does. Agent text never becomes part of the capture template, because the =%(...)= escapes in a template evaluate Lisp. The tools substitute the text after template expansion, so =%= characters stay literal.

** Known gaps

Entries of an agenda buffer named by =buffer_name= are used as they appear there, even when they come from files outside the allowed set, because you built the buffer. Org's =#+include:=, =#+setupfile:= and similar keywords aren't filtered from captured bodies.
